# steering-xling

A small, complete and honestly reported activation-steering experiment, run in October 2026. A sentiment direction is extracted from the residual stream of an open-weight model (Qwen2.5-1.5B-Instruct) using English sentence pairs only, then added back at different layers and strengths. The question is whether it shifts the sentiment of generated text, and whether the same English-built vector still steers the model when the prompt is in Arabic. Every effect is measured against a noise floor, a random-direction control and a plain prompting baseline, and its side effects on fluency, language and repetition are recorded too.

**Read [`REPORT.md`](REPORT.md) for the results.** It opens with the limits: one small model, one behaviour, automatic scorers, model-generated data and a single sweep run. In short: in English the vector shifts sentiment only narrowly beyond a random direction; in Arabic the founder's reading finds no tone transfer, and negative steering pushes the output out of Arabic; asking for the tone in the prompt works better in both languages.

## Run it

Python 3.12 or later (the pinned NumPy needs it). From the repository root:

```bash
pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu   # or the CUDA build on a GPU
pip install -r requirements.txt

python -m pytest -q                                          # CPU, no downloads
python -m src.run_sweep --config config.yaml --grid smoke    # reduced grid on Qwen2.5-0.5B, CPU
python -m src.plots --csv results/results.csv --out results/figures
```

- `run_sweep` takes `--grid full|smoke` (default `full`) and `--model dev|main` (default: `dev` for smoke, `main` for full). It downloads the model and scorers from Hugging Face, uses a GPU when one is present, and writes `results/results.csv` and `results/samples.jsonl`. A rerun skips every condition already in the CSV, so it resumes after a crash.
- The full sweep took 5.6 hours on a Colab T4. `notebooks/colab.ipynb` runs it there and keeps the results in Google Drive.
- The second pass runs with `--config config.followup.yaml`. It uses the same fingerprint, so starting from the committed `results/results.csv` adds only the new conditions.
- `plots` reads only the CSV and needs no GPU. It reads `config.yaml` from the repository root. `--model` and `--fingerprint` are needed only when the CSV holds rows from more than one model or settings fingerprint.

## How it was built

The code, tests, data and run records were produced by Claude Code agents, test-first, with the founder (the project's author) deciding every merge, every change to the method and every reading of the Arabic outputs. Those decisions are dated in the spec and the run records. `CLAUDE.md` holds the working rules the agents followed, `plans/` the per-slice plans, and `docs/tdd-evidence/` the evidence that each test failed before the code made it pass.

The contrast pairs, prompts, reference sentences and their Modern Standard Arabic translations were generated by a Claude Haiku agent and checked by `tests/test_data.py`. The founder reviewed the Arabic.
